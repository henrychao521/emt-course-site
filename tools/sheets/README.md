# 小測驗匿名作答紀錄 → Google 試算表

學生每完成一組 10 題，網站會把「各題題號、對錯、所選答案」匿名送到老師的 Google 試算表，用來分析每一題的難度、鑑別度與誘答選項。**不收姓名、班級、座號**；成果報告（含學生填的班級座號）仍然只在學生的瀏覽器裡產生，不會上傳。

`tools/site_config.json` 的 `SHEET_ENDPOINT` 預設是空字串：**沒有設定就完全不送**，網站照常運作，頁面也不會出現作答紀錄說明。

## 檔案

| 檔案 | 用途 |
|---|---|
| `Code.gs` | 貼到 Apps Script 的程式：接收（`doPost`）、驗證、寫入、分析（`analyze`）、選單 |
| `test_code_gs.js` | Code.gs 的離線模擬測試（假 SpreadsheetApp），`node tools/sheets/test_code_gs.js` |
| `send_test.py` | 網站送出端的端對端測試（本機假 endpoint＋Playwright），`python3 tools/sheets/send_test.py` |
| `../site_config.json` | 網站端設定：`SHEET_ENDPOINT`、`SHEET_TOKEN` |

## 老師的設定步驟（約 10 分鐘，只要做一次）

1. **建立試算表**：到 Google 雲端硬碟 → 新增 → Google 試算表，命名例如「EMT 小測驗作答紀錄」。建議用學校或教學用帳號。
2. **開啟 Apps Script**：試算表選單「擴充功能 → Apps Script」。會開一個綁在這份試算表上的專案。
3. **貼上程式**：把編輯器裡預設的 `Code.gs` 內容全部刪掉，貼上本資料夾 `Code.gs` 的全部內容，按儲存（磁碟圖示）。
   - 若要用共用口令，把開頭 `CONFIG.TOKEN: ''` 改成例如 `'emt-2026'`（只用英數符號）。
   - 不需要一列一題的 `items` 工作表，把 `WRITE_ITEMS` 改成 `false`。
4. **部署為網路應用程式**：右上角「部署 → 新增部署作業」→ 齒輪選「網頁應用程式」：
   - 說明：隨意，例如「EMT 紀錄 v1」
   - **執行身分：我**（你的帳號；程式才能寫入你的試算表）
   - **具有存取權的使用者：任何人**（學生不必登入；選其他選項學生會送不進來）
   - 按「部署」。第一次會要求授權：選你的帳號 →「進階 → 前往（專案名稱）（不安全）」→ 允許。這是 Google 對「自己寫、未經審查的程式」的標準警告；程式只存取這份試算表。
5. **複製網址**：部署完成畫面的「網頁應用程式網址」，形如 `https://script.google.com/macros/s/……/exec`。用瀏覽器打開它，應看到「EMT 小測驗作答紀錄接收端運作中」。
6. **填回網站**：編輯 `tools/site_config.json`：
   ```json
   "SHEET_ENDPOINT": "https://script.google.com/macros/s/……/exec",
   "SHEET_TOKEN": "emt-2026"
   ```
   `SHEET_TOKEN` 要和第 3 步的 `CONFIG.TOKEN` 相同（沒設口令就兩邊都留空）。
7. **重新產生網站**：`python3 tools/build.py`，然後 commit、push（GitHub Pages 更新後生效）。
8. **自我測試**：打開網站小測驗，把一組 10 題做完，回到試算表應出現 `responses`（與 `items`）工作表和一列新資料。重新整理試算表後，選單列會出現「EMT 分析」。

**改了 Code.gs 之後**：要到「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本：新版本 → 部署」，網址不變但程式才會更新；只按儲存不會生效。

## 資料欄位

學生端送出的 JSON（`Content-Type: text/plain`，避免 CORS 預檢）：

```json
{"v":1,"token":"","rid":"32 個 16 進位字元","bank":"2026-09-29","round":1,
 "items":[{"q":"q011","h":"9e20850b","t":"single","ok":1,"a":"C","k":"C"}, …]}
```

| 欄位 | 意思 |
|---|---|
| `rid` 作答編號 | 每組 10 題重新用 `crypto.getRandomValues` 產生的隨機編號，只用來擋重複送出；**不能**把兩組連回同一個學生 |
| `bank` 題庫版本 | 題庫 `version` |
| `round` 第幾組 | 這次開頁後的第幾組（重新整理頁面會從 1 開始） |
| `q` 題號 | `q001`～`q999` |
| `h` 版本 | 該題題幹、選項、答案的指紋（8 碼）。題目一改，指紋就變，新舊版分開統計 |
| `t` 題型 | single 單選、tf 是非、scenario 情境判斷、order 排序 |
| `ok` 對錯 | 1 答對、0 答錯 |
| `a` 所選 | 選擇題：選項代號，**對應教師版頁面該題 A、B、C、D 的順序**（學生畫面上的選項是打亂的，這裡已換回教師版代號）；是非題：`正確`／`錯誤`；排序題：學生依序點選的步驟序號，例如 `2>1>3>4`（序號＝教師版「正確順序」的第幾步） |
| `k` 正解 | 同上格式的正確答案 |

試算表工作表：

- **responses**（一列一次作答組）：時間戳（伺服器端產生）、作答編號、題庫版本、第幾組、題數、答對數，接著每題 5 欄 `題n_題號／版本／對錯／所選／正解`（最多 20 題）。
- **items**（一列一題，可關閉）：時間戳、作答編號、題庫版本、第幾組、題序、題號、版本、題型、對錯、所選、正解。適合直接做樞紐分析表（插入 → 樞紐分析表，列＝題號、值＝對錯的平均）。
- **item_stats**（按「EMT 分析 → 重新計算」產生，每次重算會整張重寫）。
- **item_stats_說明**：計算時間、作答組數、各指標定義與限制。

所有欄位都存成純文字，避免 `1>2>3`、`2026-09-29` 或全數字的作答編號被自動轉成日期或數字。

## 防濫用

網址是公開的（寫在網頁裡），所以接收端只相信「格式完全正確」的資料：

- **嚴格驗證**：只接受上述欄位，多一個欄位（例如有人塞 `class`、`seat`）就整筆拒收；題號必須符合 `q` 加 3 位數字；作答編號必須是 32 個小寫 16 進位字元；所選／正解只能是 A–F、正確／錯誤或 `數字>數字…`，長度 ≤ 20；對錯必須和「所選是否等於正解」一致；同一組內題號不可重複；題型要和答案格式相符。
- **單次最多 20 題**、整筆最多 8000 字元。
- **同一作答編號只收一次**：學生端離線補送或重送都不會重複計算。
- **可選的共用口令**：`CONFIG.TOKEN` 與網站 `SHEET_TOKEN` 相同才收。**口令寫在公開網頁裡，任何人看原始碼都拿得到，只能擋亂槍掃描的機器人，不是保密**。
- 寫入時用 `LockService` 排隊，避免同時送達時互相覆蓋。

這些做法擋得住格式錯誤與隨手亂送，擋不住「照格式偽造大量資料」。若懷疑被灌資料：看 `responses` 的時間戳是否在上課時段以外大量出現、`答對數` 是否異常一致；可以在「部署 → 管理部署作業 → 封存」立即停止接收，再新增部署換一個網址。

## 學生端的送出行為

- 一組 10 題**全部作答完成**時自動送出一次；中途換組、產生成果報告都不會多送。
- 送不出去（離線、學校網路擋住）時存在瀏覽器 localStorage 佇列，恢復連線或下次開頁自動補送；佇列最多 50 筆，超過丟最舊的。
- 無痕視窗或瀏覽器禁止儲存時，仍會直接送一次，只是送不到就不會補送。
- 因為用 `no-cors` 送出，網頁讀不到 Apps Script 的回應；只要沒有網路錯誤就當作送達。被接收端拒收的資料（格式錯誤）不會再重送。

## 怎麼看 item_stats

每一列是一題（同一題改版後會有多列，以「版本」區分）。

| 欄位 | 定義 | 怎麼讀 |
|---|---|---|
| 作答人次 | 有做到這題的作答組數 | < 30 時「提示」欄標「樣本不足」，指標只供參考 |
| 答對率 p（難度） | 答對人次 ÷ 作答人次 | 越大越容易；約 0.3–0.8 最能區分程度；≥ 0.9 標「偏易」、≤ 0.2 標「偏難」 |
| 高低分組各幾人 | 有做這題的作答組中，依該組 10 題總答對率排序，取前、後各 27%（四捨五入） | 同分時以作答編號排序決定分組 |
| 鑑別度 D | 高分組答對率 − 低分組答對率 | 常用參考：≥ 0.4 佳、0.3–0.39 尚可、0.2–0.29 待改進、< 0.2 建議修改或刪除 |
| 點二系列相關 | 該題對錯（0/1）與「同一組其餘題答對率」的 Pearson 相關（已扣掉本題，避免自我膨脹） | 一般 ≥ 0.2 可接受；**負值通常代表答案標錯或題意誤導**，會在提示欄標出 |
| 正解、選項分布 | 全體／高分組／低分組各選項被選次數與比例，正解標 ＊ | 誘答力分析：沒人選的錯誤選項沒有作用；**高分組比低分組更常選的錯誤選項**會在提示欄標出，常是題意模糊或答案有爭議 |

排序題的選項分布只列最常見的 3 種點選順序，可以看出學生最常搞混哪兩步。

### 矩陣抽樣下的限制

這個測驗每組是從題庫隨機抽 10 題，每個學生做的題目不同（矩陣抽樣），所以：

1. **「總分」不等於能力**：每組題目難易組合不同，抽到簡單組的學生分數會偏高，高低分組只是近似代表程度高低。題目越多組、作答越多，這個偏差越會平均掉。
2. **每題樣本比作答組數少很多**：題庫約 100 題、每組 10 題，平均每題只有作答組數的 1/10。要讓每題都超過 30 人次，大約需要 300 組以上的作答。
3. **作答組不是獨立的學生**：同一個學生可能做好幾組（本系統刻意不識別學生），同一人重複作答會讓樣本看起來比實際多，也可能因為看過解說而第二次答對。
4. **改版分開算**：題目改了內容，版本指紋就變，舊版的資料不會混進新版。
5. 這些是古典測驗理論的描述指標，適合找出「需要檢查的題目」，不適合拿來比較學生或班級。

## 匯出 CSV

在試算表點選要匯出的工作表分頁（例如 `item_stats` 或 `items`）→ 選單「檔案 → 下載 → 逗號分隔值（.csv）」。一次只會匯出目前這一個工作表。CSV 是 UTF-8 編碼，用 Excel 開若中文亂碼，改用 Excel「資料 → 從文字/CSV」匯入並選 UTF-8。

## 安全與隱私說明

- **不收個人資料**：送出內容只有上表的欄位，沒有姓名、班級、座號、學號、電子郵件；成果報告輸入的班級座號只用來在學生自己的瀏覽器裡畫 JPG，不會送出（已用自動測試確認）。
- **不記錄 IP**：Apps Script 網路應用程式本來就拿不到送出者的 IP 或裝置資訊，程式也沒有嘗試收集。
- **作答編號不能追蹤到人**：每組重新隨機產生，不存 cookie、不做瀏覽器指紋。
- **但 Google 會有存取紀錄**：資料存在老師的 Google 帳號，Google 依其服務條款會有伺服器端的存取與執行紀錄（Apps Script「執行作業」頁面看得到每次執行的時間）；學生的瀏覽器與學校網路也可能留有連線紀錄。對學生說明時請說「匿名」而不是「完全不留痕跡」。
- 試算表請不要設為公開分享；需要給其他老師看時，分享 `item_stats` 的下載檔即可。
- 學生頁面在有設定網址時會顯示：「完成一組後，會匿名送出各題對錯與所選答案（不含班級座號與任何個人資料），供老師分析題目品質。」教師版頁面也有一段資料流向說明。
