# 小測驗作答紀錄 → Google 試算表（第 2 版）

學生每完成一組 10 題，網站會把「各題題號、對錯、所選答案」送到老師的 Google 試算表，用來分析每一題的難度、鑑別度與誘答選項。學生若按「成果報告產生」，當時填的**班級與座號**會再送一次，補進同一組的紀錄，供學習紀錄與題目分析；沒有產生報告的組別不含班級座號。成果報告圖片本身仍然只在學生的瀏覽器裡產生，不會上傳。

`tools/site_config.json` 的 `SHEET_ENDPOINT` 空字串時**完全不送**，網站照常運作，頁面也不會出現作答紀錄說明。

## 檔案

| 檔案 | 用途 |
|---|---|
| `Code.gs` | 貼到 Apps Script 的程式：接收（`doPost`）、驗證、寫入、班級座號補登、匯入題庫（`importBank`）、分析（`analyze`）、選單 |
| `fake_gas.js` | Apps Script 的最小假物件（試算表、鎖、UrlFetchApp），測試共用 |
| `test_code_gs.js` | Code.gs 的離線模擬測試，`node tools/sheets/test_code_gs.js` |
| `send_test.py` | 網站送出端的端對端測試（本機假 endpoint＋Playwright），`python3 tools/sheets/send_test.py` |
| `../site_config.json` | 網站端設定：`SHEET_ENDPOINT`、`SHEET_TOKEN` |
| `../../assets/quiz-bank-index.json` | `build.py` 產生的題庫索引（題號 → 題幹、選項文字、正解代號），給 `importBank` 抓 |

## 第一次設定（約 10 分鐘，只要做一次）

1. **建立試算表**：Google 雲端硬碟 → 新增 → Google 試算表，命名例如「EMT 小測驗作答紀錄」。建議用學校或教學用帳號。
2. **開啟 Apps Script**：試算表選單「擴充功能 → Apps Script」。
3. **貼上程式**：刪掉編輯器裡預設的內容，貼上本資料夾 `Code.gs` 全部內容，按儲存（磁碟圖示）。
   - 要用共用口令：把 `CONFIG.TOKEN: ''` 改成例如 `'emt-2026'`（只用英數符號）。
   - 不需要一列一題的 `items` 工作表：把 `WRITE_ITEMS` 改成 `false`。
4. **先授權**：編輯器上方函式選單選 `importBank` → 按「執行」。會跳出授權視窗（見下方「授權提示」），允許後會建立「題庫」工作表。
5. **部署為網路應用程式**：右上角「部署 → 新增部署作業」→ 齒輪選「網頁應用程式」：
   - **執行身分：我**（程式才能寫入你的試算表）
   - **具有存取權的使用者：任何人**（學生不必登入）
   - 按「部署」，複製「網頁應用程式網址」（`https://script.google.com/macros/s/……/exec`）。用瀏覽器打開，應看到「EMT 小測驗作答紀錄接收端運作中」。
6. **填回網站**：`tools/site_config.json` 的 `SHEET_ENDPOINT` 填這個網址，`SHEET_TOKEN` 填第 3 步的口令（沒設就留空）。執行 `python3 tools/build.py`，commit、push。
7. **自我測試**：做完一組 10 題、產生一次成果報告，試算表 `responses` 應出現一列並帶班級座號。測完把這列刪掉（見「刪除測試列」）。

## 更新 Code.gs（例如這次升到第 2 版）

**網址不會變，網站不必重新設定。**

1. 試算表「擴充功能 → Apps Script」，把 `Code.gs` 內容**全部**換成新版（若原本改過 `CONFIG.TOKEN` 或 `WRITE_ITEMS`，記得改回你的設定），按儲存。
2. **先授權新權限**：函式選單選 `importBank` → 執行。第 2 版新增「連線到外部服務」權限，會再跳一次授權視窗（見下方）。**這一步要在部署前做**：新權限沒授權前，網路應用程式可能無法接收資料。
3. 「部署 → 管理部署作業」→ 選目前的部署 → 右上角**鉛筆（編輯）** → 「版本」下拉選**「新版本」** → 按「部署」。
   - 只按儲存**不會**生效；「新增部署作業」會產生**新網址**，不要用。
4. 回到試算表重新整理，選單「EMT 分析」會多一個「匯入最新題庫」。
5. 第 2 版第一次收到資料時，會自動在 `responses`（第 6 欄之後）和 `items`（第 4 欄之後）插入「班級」「座號」兩欄；舊資料跟著右移，不會錯位，舊列的班級座號是空白。

### 授權提示

- 第一次執行時 Google 會說「這個應用程式未經 Google 驗證」：按「進階 → 前往（專案名稱）（不安全）」。這是 Google 對「自己寫、未經審查的程式」的標準警告。
- 要求的權限：
  - **查看、編輯、建立及刪除 Google 試算表**：只用在這份綁定的試算表。
  - **連線到外部服務**（第 2 版新增，UrlFetchApp）：只用來下載 `https://henrychao521.github.io/emt-course-site/assets/quiz-bank-index.json`（本網站自己的題庫索引），不會把任何資料送出去。

## 資料欄位

學生端送出兩種 JSON（`Content-Type: text/plain`，避免 CORS 預檢）：

**作答紀錄**（每完成一組送一次）：

```json
{"v":1,"token":"","rid":"32 個 16 進位字元","bank":"2026-09-29","round":1,
 "items":[{"q":"q011","h":"9e20850b","t":"single","ok":1,"a":"C","k":"C"}, …]}
```

**identify**（按「成果報告產生」時，每組只送第一次）：

```json
{"v":1,"type":"identify","token":"","rid":"同一組的作答編號","class":"228","seat":"07"}
```

| 欄位 | 意思 |
|---|---|
| `rid` 作答編號 | 每組重新用 `crypto.getRandomValues` 產生；identify 靠它找到同一組的列 |
| `bank` 題庫版本 | 題庫 `version` |
| `round` 第幾組 | 這次開頁後的第幾組（重新整理從 1 開始） |
| `q` 題號 | `q001`～`q999` |
| `h` 版本 | 該題題幹、選項、答案的指紋（8 碼）。題目一改就變，新舊版分開統計 |
| `t` 題型 | single 單選、tf 是非、scenario 情境判斷、order 排序 |
| `ok` 對錯 | 1 答對、0 答錯 |
| `a` 所選 | 選擇題：選項代號，**對應教師版頁面該題 A、B、C、D 的順序**；是非題：`正確`／`錯誤`；排序題：依序點選的步驟序號，例如 `2>1>3>4` |
| `k` 正解 | 同上格式 |
| `class` 班級 | 中文、英文字母、數字或 `-`，1–10 字，不可用 `-` 開頭；全形數字會先轉半形 |
| `seat` 座號 | 1–4 位數字（保留前導 0，例如 `07`） |

**同一組只收第一次的班級座號**：學生改填後再按一次「成果報告產生」，網站不會再送，試算表也不會覆寫（避免被改掉）。填錯時請老師直接在試算表改那一列的「班級」「座號」（`responses` 一列、`items` 同作答編號的 10 列）。

試算表工作表：

- **responses**（一列一組）：時間戳（伺服器端）、作答編號、題庫版本、第幾組、題數、答對數、**班級、座號**，接著每題 5 欄 `題n_題號／版本／對錯／所選／正解`（最多 20 題）。
- **items**（一列一題，可關閉）：時間戳、作答編號、題庫版本、第幾組、**班級、座號**、題序、題號、版本、題型、對錯、所選、正解。適合做樞紐分析（例如列＝班級、值＝對錯的平均）。
- **題庫**（「EMT 分析 → 匯入最新題庫」產生，每次整張覆寫）：題號、版本、題型、章節、難度、題幹、正解、選項 A–F、正確步驟、題庫版本。網站題庫改版並上線後，再匯入一次即可。
- **item_stats**（「EMT 分析 → 重新計算」產生，每次整張重寫）。
- **item_stats_說明**：計算時間、作答組數、有班級座號的組數、題庫匯入狀態、各指標定義與限制。

所有欄位都存成純文字，避免 `1>2>3`、`2026-09-29`、座號 `07` 被自動轉成日期或數字。

## 防濫用

網址寫在網頁裡是公開的，所以接收端只相信格式完全正確的資料：

- **嚴格驗證**：多一個欄位（例如塞 `name`）就整筆拒收；題號 `q` 加 3 位數字；作答編號 32 個小寫 16 進位字元；所選／正解只能是 A–F、正確／錯誤或 `數字>數字…`；對錯必須和「所選是否等於正解」一致；班級座號照上表規則。
- **單次最多 20 題**、整筆最多 8000 字元。
- **同一作答編號只收一次作答紀錄、只收一次班級座號**；找不到作答編號的 identify 拒收。
- **可選的共用口令**：口令寫在公開網頁裡，**只能擋亂槍掃描，不是保密**。
- 寫入時用 `LockService` 排隊。

擋不住「照格式偽造大量資料」。懷疑被灌資料時：看時間戳是否在上課以外時段大量出現；可以在「部署 → 管理部署作業 → 封存」立即停止接收，再新增部署換網址（網站要跟著改 `SHEET_ENDPOINT`）。

## 刪除測試列

1. 在 `responses` 找到測試那幾列（看「時間戳」與「作答編號」），選取列號 → 右鍵「刪除列」。
2. 到 `items`：選單「資料 → 建立篩選器」，在「作答編號」欄篩選剛才那些編號 → 選取篩出的列 → 右鍵「刪除所選列」→ 移除篩選器。
3. 「EMT 分析 → 重新計算」。

## 學生端的送出行為

- 10 題全部作答完成時送一次作答紀錄；按「成果報告產生」且班級座號格式正確時，再送一次 identify（每組只送第一次）。格式不對時不產生報告、也不送，並提示學生改正。
- 送不出去（離線、學校網路擋住）時存在瀏覽器 localStorage 佇列，依序補送（identify 一定排在同一組作答紀錄之後）；恢復連線或下次開頁自動補送，最多 50 筆，超過丟最舊的。
- 無痕視窗或禁止儲存時仍會直接依序送一次，只是送不到就不補送。
- 用 `no-cors` 送出，網頁讀不到 Apps Script 的回應；被拒收的資料不會重送。

## 怎麼看 item_stats

每一列是一題（同一題改版後會有多列，以「版本」區分）。先「匯入最新題庫」，題幹與選項文字才會出現。

| 欄位 | 定義 | 怎麼讀 |
|---|---|---|
| 題幹 | 取自「題庫」工作表 | 版本不符時前面加「（現行版）」 |
| 作答人次 | 有做到這題的作答組數 | < 30 時提示欄標「樣本不足」 |
| 答對率 p（難度） | 答對人次 ÷ 作答人次 | 約 0.3–0.8 最能區分程度；≥ 0.9 標「偏易」、≤ 0.2 標「偏難」 |
| 高低分組各幾人 | 依該組 10 題總答對率排序，取前、後各 27% | 同分時以作答編號排序決定分組 |
| 鑑別度 D | 高分組答對率 − 低分組答對率 | ≥ 0.4 佳、0.3–0.39 尚可、0.2–0.29 待改進、< 0.2 建議修改或刪除 |
| 點二系列相關 | 該題對錯與「同一組其餘題答對率」的相關（已扣掉本題） | 一般 ≥ 0.2 可接受；**負值通常代表答案標錯或題意誤導** |
| 選項分布 | 全體／高分組／低分組，例如 `A（24 小時）：3（10%）｜B＊（56 小時）：20（67%）` | 括號內是選項文字前 12 字，＊為正解；沒人選的錯誤選項沒有作用；**高分組比低分組更常選的錯誤選項**會在提示欄標出 |
| 提示 | 自動判讀 | 「題目已修改，舊版作答」＝作答時的版本指紋和目前題庫不同，這列只代表舊版，選項文字不套用；「題庫中找不到這個題號」＝題目已刪除或尚未匯入最新題庫 |

排序題的選項分布只列最常見的 3 種點選順序。

### 矩陣抽樣下的限制

每組從題庫隨機抽 10 題，每個學生做的題目不同：

1. **「總分」不等於能力**：題目組合難易不一，高低分組只能近似代表程度高低。
2. **每題樣本比作答組數少很多**：題庫約 100 題、每組 10 題，平均每題只有作答組數的 1/10；要每題都超過 30 人次，大約需要 300 組以上。
3. **作答組不是獨立的學生**：同一個學生可能做好幾組（有填班級座號的組別可以辨識，沒填的不行），重複作答也可能因看過解說而答對。
4. **改版分開算**：版本指紋改變後，新舊版資料不混在一起。
5. 這些是古典測驗理論的描述指標，適合找出「需要檢查的題目」，不適合拿來比較學生或班級。

## 匯出 CSV

點選要匯出的工作表分頁 → 「檔案 → 下載 → 逗號分隔值（.csv）」（一次只匯出目前這一張）。Excel 開啟中文亂碼時，改用「資料 → 從文字/CSV」匯入並選 UTF-8。

## 安全與隱私說明

- **不再是完全匿名**：沒有產生成果報告的組別只有題號、對錯、所選答案；**產生成果報告的組別含學生填的班級與座號**，可以對應到個人。請把試算表當成含學生個資的成績資料保管：不要公開分享、只分享給需要的老師，學期結束後依學校規定保存或刪除。
- 學生頁面在有設定網址時會顯示：「完成一組後，會送出各題對錯與所選答案給老師；按『成果報告產生』時，填寫的班級座號也會一起送給老師，用於學習紀錄與題目分析。成果報告圖片本身只在你的瀏覽器裡產生，不會上傳。」教師版頁面也有資料流向說明。
- **不收姓名、學號、電子郵件**；成果報告圖片不上傳。
- **不記錄 IP**：Apps Script 網路應用程式本來就拿不到送出者的 IP 或裝置資訊。
- **Google 會有存取紀錄**：資料存在老師的 Google 帳號，Google 依其服務條款有伺服器端的執行紀錄；學生的瀏覽器與學校網路也可能留有連線紀錄。
- 給其他人看分析結果時，分享 `item_stats` 的下載檔即可（不含班級座號）。

## 測試

測試**一律用本機假 endpoint**，不要對正式網址送資料。`send_test.py` 會另外複製一份網站、用環境變數 `EMT_SHEET_ENDPOINT` 改成本機網址再 build，並擋掉瀏覽器對 script.google.com 的所有請求。手動測其他腳本（例如 `tools/quizgen/play_test.py`）時，也要先用 `EMT_SHEET_ENDPOINT= python3 tools/build.py` 產生不送資料的版本，測完再正常 build。

```bash
node tools/sheets/test_code_gs.js      # 驗證、寫入、identify、欄位遷移、importBank、分析指標（手算小例＋400 組隨機資料對獨立實作）
python3 tools/sheets/send_test.py      # 3 組（2 組產生報告）、格式錯誤、離線依序補送、上限 50、未設定時完全不送，最後把收到的資料交給 Code.gs 驗試算表
```
